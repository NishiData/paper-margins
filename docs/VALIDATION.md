# 確認結果 — 2026-10-14

## 1.0.8の追加確認

- PDFの注釈と接続していないChatGPTの模擬画面で、初期表示・再取得後にもパネルが出ないことを確認。
- 手動の表示操作から、既存の回答を注釈へ接続・保存できることを確認。
- 接続中のパネルを非表示にしたまま新しい回答を保存し、定期処理でパネルを再表示しないことを確認。
- 連携終了後にパネルを表示しないことと、PDFからの新しい接続で表示することを確認。
- バックグラウンドのコマンド処理が、ChatGPTのアクティブタブへ表示切り替えを送り、他サイトへ送らないことを確認。

Chromeのキーボードショートカットイベントと拡張APIは模擬実装です。実際にログインしたChatGPT画面での確認とは区別しています。

## 1.0.7の追加確認

- 長いPDF・注釈がある画面で、ウィンドウ全体が下へスクロールして空白を表示しないことを確認。

- 注釈パネル内のスクロールと、スクロール後の閉じる操作を確認。

## 1.0.6の追加確認

ユーザーの画像で、注釈のオーバーレイがツールバー右端の「注釈」ボタンを覆っていることを確認しました。注釈パネル内に閉じるボタンを追加し、見出しを固定表示するように変更しました。

ブラウザの確認では、広い画面・中間幅・狭い画面・ChatGPT連携後のcompact表示で、パネル内の閉じるボタン、上部の再表示ボタン、Escを確認しました。注釈パネルをスクロールした後も閉じるボタンをクリックできること、閉じて開いても入力した質問が残ることを確認しています。保存処理・保存形式は変更していません。

## 1.0.5の追加確認

ユーザーのスクリーンショットで、保存ボタンが回答検出に失敗していることを確認しました。実画面のDOMは未取得のため、原因が判明したとは扱っていません。

- 未知の構造で回答を取得できない場合、貼り付け保存欄を自動で開くことを確認。
- 貼り付けた日本語・複数行・LaTeXを、実装したバックグラウンド処理経由で指定PDFのページ注釈へ保存することを確認。
- 同じ質問・回答の保存を繰り返しても重複しないことを確認。
- 空欄・接続解除・書き込み失敗では成功と表示せず、失敗時に貼り付けた下書きを残すことを確認。
- ページを作り直しても保存済みの回答と接続先を保持することを確認。
- 診断JSONのダウンロードと、会話本文・入力欄の値を含めないことを確認。
- 既存の自動・手動保存と選択テキスト保存のテストも通過。

ブラウザと実装済みのバックグラウンド処理を接続した模擬環境での確認です。Chromeの保存APIはテスト用の実装を使用しました。実際のChatGPT画面での自動取得・保存は未確認です。

## 1.0.4の追加確認

- 非表示の停止ボタンが残る画面を再現し、完了済み回答が自動保存されることを確認。
- 停止ボタンが見えている場合でも、手動保存で表示済みの回答を保存できることを確認。
- role属性、turn属性、会話のarticle、Markdown本文などの異なる構造で、質問と回答を取得する処理を確認。
- 読み取れない構造の画面でも、選択した回答の文字列を保存できることを確認。
- 書き込み失敗を、保存成功として表示しないことを確認。
- 再質問せず、既存の回答を選択したPDF注釈へ再接続して保存することを確認。

いずれも模擬画面とブラウザテストでの確認です。実際のChatGPT画面での保存を確認済みとはしていません。

## 1.0.3の追加確認

- PDFの範囲選択からPNGを作成し、範囲内の文字とともに質問へ紐づけることを確認。
- 模擬ChatGPT画面で、質問と実際の切り抜きPNGを一緒に入力し、ファイル欄に画像が渡ることを確認。
- file input / pasteでの画像の受け渡し、PNGクリップボード用データ、添付の確認ができない場合を区別する処理を確認。
- 同じ質問が残る会話のURL変更後も自動保存が続き、別の会話に移動した場合は保存が停止することを確認。
- 選択画像が注釈の保存・復元形式で維持されることを確認。

画像添付の確認も模擬画面でのテストです。実際にログインしたChatGPTでの自動添付を確認済みとはしていません。画像が入力欄に見えない場合は、画像コピーまたはPNG保存で手動添付してください。

## 確認済み

- 複数ページPDFの表示、テキスト選択、数式・図の範囲選択。
- ページ移動、拡大縮小、注釈の位置の保持。
- 質問・回答の追加、LaTeX数式表示、タグと検索。
- ブラウザ画面の再読み込み後もPDFと注釈を保持。
- PDF本体を含むJSONバックアップと、空の保存領域への復元。
- 会話を含むPDFコメントの出力。日本語コメントを再読み込みして検証。
- 回答中のHTMLを実行せず、文字として表示。
- 模擬ChatGPT画面で、質問欄への入力、ユーザーが送信するまで送信しない構成、回答の手動・自動保存、既存回答の除外、重複保存の抑制、数式のLaTeX抽出。
- バックグラウンド処理の模擬環境で、同時に届いた複数の回答とタグ編集を取りこぼさず保存。不許可の送信元や連携終了後の保存を拒否。
- JavaScript構文、マニフェスト、ローカル依存ファイル、フォント参照。
- 日本語UIの表示をスクリーンショットで確認。

PDF画面の確認にはChromiumのヘッドレス環境を使い、Chrome拡張APIはテスト用の実装に置き換えました。座標・データ形式・重複更新・画像保存・会話判定についてはNodeの7件のテストが通っています。

## この環境で確認できていないもの

- デスクトップ版Chrome / Edgeに拡張機能として実際に読み込む操作。
- ログインした実際のChatGPTの現行画面との連携。
- 全種類のPDF、スキャン・暗号化PDF、縦書き・複雑な文字配置の網羅的な検証。

この環境のヘッドレスブラウザでは拡張機能のサービスワーカーを起動できなかったため、拡張APIとChatGPT画面の確認は上記の模擬環境で行っています。Chrome拡張としての実機確認を済ませたとは扱っていません。

自動保存が動かない場合は連携パネルの「最新の回答を保存」、またはPDF画面の「質問・回答を手入力で保存」を使えます。
